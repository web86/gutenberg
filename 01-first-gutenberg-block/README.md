# День 01 — Создаём свой первый блок Gutenberg

**Серия:** Gutenberg с нуля — 1/30  
**Дата:** 6 ноября 2026  
**Цель:** научиться создавать и подключать собственный блок WordPress.

> В этом уроке мы создадим простейший блок **Web86 Hello**, который показывает на странице фразу: «Привет! Это мой первый блок Gutenberg.» Пока без сложных настроек — в следующих уроках добавим редактируемый текст и другие возможности.

## Зачем нужны собственные блоки

В редакторе WordPress (Gutenberg) каждый абзац, изображение и кнопка — отдельный блок. У разработчика есть возможность создавать **свои блоки** с нужным дизайном и поведением. Например, карточку услуги, FAQ, Hero-секцию или каталог товаров.

В отличие от многократного копирования HTML, такой блок можно вставлять через обычный редактор и переиспользовать на разных страницах.

За 30 уроков мы соберём собственную коллекцию **Web86 Blocks**. Начинаем с малого.

## Что потребуется

- Локальная установка WordPress с доступом к `wp-content/plugins`.
- Node.js и npm для разработки (современная поддерживаемая версия Node.js).
- Любой редактор кода.
- Терминал.

Node.js нужен **только разработчику**, для сборки JavaScript. На хостинге WordPress он не обязателен.

Проверь установленные версии:

```bash
node -v
npm -v
```

## Способ 1: создаём основу официальным инструментом

Открой терминал в `wp-content/plugins` локального WordPress и выполни:

```bash
npx @wordpress/create-block@latest hello --namespace=web86 --title="Web86 Hello"
cd hello
npm start
```

Генератор создаст плагин и настроит сборку. В админке WordPress активируй **Web86 Hello** в разделе **Плагины**.

Затем замени файлы в папке `src` кодом из раздела ниже или скопируй готовую папку [web86-hello](./web86-hello/) из этого репозитория.

## Способ 2: используем готовый исходный пример

В папке [web86-hello](./web86-hello/) лежит самодостаточный исходный код учебного плагина. Скопируй эту папку в `wp-content/plugins`, открой терминал внутри неё и выполни:

```bash
npm install
npm run build
```

После этого активируй плагин в WordPress.

> В репозитории хранятся исходники. Папка `build` генерируется при сборке и не хранится в Git.

## Как всё работает

1. `block.json` — «паспорт» блока: имя, иконка, файлы.
2. `index.js` — регистрирует блок в редакторе.
3. `edit.js` — то, что пользователь видит в редакторе.
4. `save.js` — HTML, сохраняемый вместе со страницей.
5. `style.scss` — стили на сайте и в редакторе.
6. `editor.scss` — дополнительные стили только для редактора.
7. `web86-hello.php` — подключает собранный блок к WordPress.

Сегодня блок **статический**: HTML страницы формируется функцией `save()`. Для динамических блоков с PHP будет отдельный урок.

## Проверяем результат

Открой в WordPress редактор новой страницы, нажми **+**, найди **Web86 Hello**, вставь и сохрани страницу. Ты увидишь фразу:

**Привет! Это мой первый блок Gutenberg.**

На опубликованной странице текст появится на голубом фоне. В редакторе добавится пунктирный контур.

Если блок не появился: проверь активацию плагина, результаты `npm run build`, файлы в `build` и ошибки консоли браузера.

## Домашнее задание

Поменяй фразу **одновременно** в `src/edit.js` и `src/save.js`. Затем поменяй фон в `src/style.scss`, выполни сборку и создай новую страницу с изменённым блоком.

Почему одновременно? Если HTML в `save.js` отличается от ранее сохранённого, WordPress может посчитать старый блок невалидным. Разберём правила сохранения в следующих уроках.
